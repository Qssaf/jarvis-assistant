# Revamp Implementation Plan

> **For agentic workers:** executed natively in one session. One small read-only workflow (4 readers) finds reliability
> bugs; every fix is made and checked inline. Steps use checkbox syntax for tracking.

**Goal:** Jarvis copes better: several API keys per provider that take over from each other, the reliability bugs a
whole-app read finds fixed, and the window's look tightened, without rewriting what the checks already protect.

**Architecture:** Rebuilt in place. A provider's keys live newline-separated in its one keychain entry, so every old
caller of `store.secret` keeps working (it returns the first). `brain.Keys` rotates inside a backend, below the model
chain: the chain only sees a provider as busy when every key is. The voice keeps its own index (`brain.live_key`).

**Tech Stack:** Python 3.13, Qt Quick/QML, plain asserts in `test_jarvis.py`.

**Spec:** this file (the user said "just dive in" on 2026-11-13, then "keep the revamp", away for an hour).

## Decisions (the user's)
- A whole-app pass: UI, features, handling things better, several API keys from the same provider.
- Few subagents. Questions only when needed.

## Decisions (mine)
- No rewrite from zero: 5,300 lines of checks hold fixes that a rewrite would lose.
- Keys: one at a time, sticky (the one that answered last takes every request), like the Google accounts. A 429 rests a
  key for that model as long as the reply says; a refused key (401/403, Gemini's `API_KEY_INVALID`) rests for every
  model for `KEY_REST` (600 s). One key: nothing changes.
- Gemini's 400 "API key not valid" stops being `BadRequest` (it ended the whole model chain): it's the key's fault.
- Pasting a key adds it (it used to replace); each saved key shows its last four characters and can be removed alone.
- Gemini Live tries each key once when a session can't be opened, then the backup voice as before; WhatsApp calls use
  the key Live is on.
- The window keeps the "glass" look and `Theme.qml`'s tokens (shared with the phone app's `Theme.kt`).

## Review Focus
- A key that's revoked while others work: no task fails, no "isn't answering" notice.
- Every key resting: the chain is told how long (no "hi" probe), nothing is sent.
- A saved key must never appear in a result, a log line or the window (only its last four characters).
- A spoken passphrase with spaces still reads back whole from `store.secret`.
- Removing a key while a request is in flight on it.

### Task 1: Several keys per provider
**Files:** `store.py`, `brain.py`, `jarvis.py`, `whatsapp.py` (unchanged call), `qml/ModelsPage.qml`, `translations/`,
`test_jarvis.py`, `CHANGELOG.md`, `CLAUDE.md`.

**Interfaces:**
- `store.secrets(name) -> list[str]`; `store.secret(name) -> str` (the first, or `""`).
- `brain.Overloaded(msg, retry_after=None, key=False)`; `http_error` sets `key=True` for 429, 401, 403 and a refused key.
- `brain.Keys(keys)`: `.keys`, `.idx`, `.resting`, `.each(model, send) -> send(key)'s answer`, `.state() -> [{"tail", "resting"}]`.
- `brain.gemini_keys() -> list[str]` (raises `RuntimeError` when none); `brain.live_key = [0]`; `brain.api_key()`.
- `OpenAICompatible(name, url, key="")`: `key` a string or a list.
- `POST /api/keys/<name>`: `{key}` adds, `{remove: i}` removes the i-th, `{key: ""}` removes all.
- `models_info()` rows: `keys: [{"tail": "…abcd", "resting": seconds}]`.
- `Live._next_key() -> bool`: another key to open a session with this round.
