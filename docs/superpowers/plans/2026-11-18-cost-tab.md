# Cost tab Implementation Plan

> **For agentic workers:** executed natively in one session (the user's CLAUDE.md); only the translations go to one
> subagent. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Cost" page showing what Jarvis's model use would cost at Google's paid-tier prices, per day and per model.

**Architecture:** Each backend turns its reply's token counts into one normalized dict and adds it to `DATA/usage.json`
(per day, per `"backend model"`, beside the request count Health already shows). `brain.cost_report(days)` prices it
from a built-in, dated table; `GET /api/cost?days=N` serves it; `qml/CostPage.qml` draws it.

**Tech Stack:** Python 3.13, Qt Quick/QML, plain asserts in `test_jarvis.py`.

**Spec:** `docs/superpowers/specs/2026-11-18-cost-tab-design.md`

## Global Constraints
- Nothing leaves the PC; no new dependency.
- Prices: USD per 1M tokens, Google's pricing page on 2026-11-18, paid tier, Standard (see Task 1's table).
- 90 days of usage kept. `brain.usage_today()` keeps returning `{"backend model": requests}` for Health.
- Every QML text through `qsTr()`, all 18 `.ts` files translated, `.qm` rebuilt (the tests compare them).
- CHANGELOG line; CLAUDE.md's architecture notes updated.

## Review Focus
- An old `usage.json` (`{"day", "models"}`) must still load: today's request counts carry over, nothing crashes.
- A reply without `usageMetadata` (errors, some image or TTS replies) counts the request and no tokens, never raises.
- Two threads recording at once (hedged requests) must not lose a count (one lock around read-modify-write).
- A model with no price shows tokens and "no price", and never makes the total look complete: `unpriced` says how many.
- A day spanning a price change (2026-12-31 vs 2027-01-01) prices each day at its own rate.

### Task 1: Recording and pricing (brain.py)

**Files:** Modify `brain.py` (next to `count_use`), `test_jarvis.py`.

**Interfaces (produces):**
- `gemini_usage(meta: dict | None) -> dict`: `{"in": {mod: n}, "out": {mod: n}, "cached": n}`; modality keys lower-case
  (`text`, `audio`, `image`, `video`, `document`); accepts both `candidates*` (generateContent) and `response*` (Live)
  keys; thoughts and tool-use prompt tokens added to `out.text` / `in.text`; cached taken out of `in.text`.
- `openai_usage(u: dict | None) -> dict`: same shape from `prompt_tokens`, `completion_tokens`,
  `prompt_tokens_details.{cached_tokens,audio_tokens}`, `completion_tokens_details.audio_tokens`.
- `count_tokens(backend: str, model: str, usage: dict) -> None`: adds into today's entry; never raises on an empty dict.
- `count_use` unchanged in signature: now writes `{"days": {day: {key: {"requests", "in", "out", "cached"}}}}`,
  converting the old format; drops days older than `USAGE_DAYS = 90`.
- `PRICES: dict[str, list[dict]]`: per model, tiers `{"until"?: "YYYY-MM-DD", "in", "out", "cached"?, "in_audio"?,
  "in_image"?, "out_audio"?, "out_image"?}`; the first tier whose `until` is on or after the day (or has none) applies.
- `price_of(model: str, day: str) -> dict | None`; `cost_of(usage: dict, prices: dict) -> float` (per-modality key
  `in_<mod>` / `out_<mod>`, else `in` / `out`; cached at `cached`, else `in`).
- `cost_report(days: int = 1) -> {"total": float, "tokens": int, "unpriced": int, "days": [{"day", "cost"}],
  "models": [{"key", "requests", "input", "output", "cost": float | None}]}`: oldest day first, every day present;
  models costliest first, unpriced last.

### Task 2: Every backend records (brain.py, jarvis.py, whatsapp.py)

**Interfaces (consumes):** Task 1's normalizers and `count_tokens`.
- `AIStudio.generate`: `count_tokens("aistudio", model, gemini_usage(d.get("usageMetadata")))` on a good reply.
- `Antigravity.generate`: the same from `response.usageMetadata`, under the Jarvis-facing model name (before
  `antigravity_model` renames it).
- `OpenAICompatible.generate` (chat only): `count_tokens(self.name, model, openai_usage(d.get("usage")))`.
- `Live._handle`: `m.usage_metadata` → `count_use` + `count_tokens("aistudio", live_model, gemini_usage(dump))` where
  `dump = m.usage_metadata.model_dump(by_alias=True, mode="json", exclude_none=True)`; the same in whatsapp.py's call
  session receive loop.

- [ ] Failing checks: a fake AI Studio reply with `usageMetadata` shows in `cost_report(1)`; a Live server message with
  `usage_metadata` (real `genai.types.LiveServerMessage`) through `_handle` does too.
